# KnowBase V4.1 — 质量加固与主体验升级设计方案

> 目标：不要继续堆功能，而是把已经完成的 Agent Runtime、Workspace、Trace Lab、Portfolio、MCP、LangGraph 能力打磨成一个安全、可信、可展示的 Agentic Learning OS。

---

## 1. 结论先行

当前 KnowBase 的问题不是“功能少”，而是：

- 功能面已经很宽，但关键链路还像 MVP。
- 前端页面可用，但主体验不够集中，Agent 执行过程不够可见。
- 后端已经有 Agent / Trace / MCP / LangGraph 的形状，但安全、审批、失败处理、工具追踪还需要补实。
- 工程质量有欠账：前端 lint 未通过，build 当前受本地 Tailwind native 依赖影响失败。

V4.1 最优方向：

```text
安全正确性优先
  -> Agent 语义真实可信
  -> 学习任务主线收拢
  -> 前端工作台升级
  -> Trace / Portfolio 面试展示增强
  -> 工程质量归零
```

一句话定位：

**KnowBase V4.1 是一个可观测、可审批、可复盘的 AI Agent 学习工作台，而不是一组分散 AI 功能入口。**

---

## 2. 三种路线对比

### 方案 A：继续加新功能

例如加浏览器插件、资料推荐、移动端、更多报表。

优点：

- 看起来功能更多。
- 短期演示菜单更丰富。

缺点：

- 当前核心链路的可信度问题仍然存在。
- 前端会更像功能堆叠。
- 面试时容易被追问安全、审批、失败恢复、可观测性，反而暴露短板。

结论：不推荐。

### 方案 B：只做前端美化

例如重做颜色、卡片、图表、首页。

优点：

- 视觉提升最快。
- 演示第一眼更舒服。

缺点：

- MCP 默认用户、审批先落库、失败 Trace 脏数据等问题仍然存在。
- Agent Workspace 只是“看起来像 Agent”，不是工程上真的可信。

结论：可以作为一部分，但不能作为主路线。

### 方案 C：质量加固 + 主体验升级

先修安全和语义，再把前端围绕“今日学习工作台 + Agent 执行过程 + Trace 回放 + Portfolio 展示”重组。

优点：

- 贴合当前代码现状，不推倒重来。
- 能直接解决最关键风险。
- 前端会从“多个简单页面”变成“一个完整学习操作系统”。
- 更适合 AI Agent 应用开发岗位展示。

结论：推荐采用。

## 3. V4.1 范围

### 做

- 修复 MCP 用户隔离和访问控制。
- 修复 LangGraph human-in-the-loop：审批前只生成草稿，审批后才落库。
- 修复 Agent Run 失败状态和 Step 失败记录。
- 打通 Tool Registry 与 ToolCall Trace。
- 统一学习路径双轨模型：普通路径生成也写结构化 module/topic/task。
- 修复前端 lint 和 build 环境问题。
- 重设计 Dashboard / Agent Workspace / Trace Lab / Portfolio 的信息架构与页面层级。
- 强化面试展示能力：代表性 Agent Run、RAG 质量、成本、失败恢复、架构说明。

### 不做

- 不增加付费、社交、移动 App、浏览器插件。
- 不重写技术栈。
- 不把所有业务强行迁移到 LangGraph。
- 不做复杂多 Agent 自主循环。
- 不新增大而全的权限系统，只做当前单用户/本地 MCP 场景下的安全边界。

## 4. 后端设计

### 4.1 MCP 安全边界

当前问题：

- `backend/app/mcp/server.py` 通过 `_get_default_user()` 取第一个用户。
- `/mcp` 在 `backend/app/main.py` 中无条件挂载。
- 外部客户端连接后可能读取或写入第一个用户的知识库。

设计：

```text
默认关闭 MCP
  -> 配置 KNOWBASE_MCP_ENABLED=true 后才挂载
  -> 配置 KNOWBASE_MCP_USER_ID 绑定明确用户
  -> 配置 KNOWBASE_MCP_TOKEN 作为本地访问 token
  -> 移除 _get_default_user()
```

第一阶段可以先做最小安全版本：

- `KNOWBASE_MCP_ENABLED` 默认 `false`。
- 未配置 `KNOWBASE_MCP_USER_ID` 时 MCP tools/resources 返回配置错误。
- `create_note_draft` 这类写工具默认进入草稿或要求显式启用写能力。
- Settings 页面显示当前 MCP 是否启用、绑定用户、连接地址。

验收标准：

- 没有任何 MCP 代码会自动读取“第一个用户”。
- 未启用 MCP 时 `/mcp` 不挂载或返回明确不可用。
- MCP 工具只能访问绑定用户的数据。

### 4.2 Human-in-the-loop 真实落地

当前问题：

- `langgraph_adapter.plan_node()` 调用 `planner.plan()`。
- `planner.plan()` 会直接创建 `LearningPath / Module / Topic / Task`。
- 之后才进入 approval 节点。
- 用户拒绝时，任务其实已经创建。

设计：

把规划拆成两段：

```text
preview_plan()
  -> 只生成结构化 JSON 草稿
  -> 不写 learning_paths / tasks

commit_plan()
  -> 审批通过后写入路径、模块、主题、任务
  -> 关联 agent_run_id
```

推荐接口语义：

```text
POST /workspace/workflow/plan
  -> diagnose
  -> preview_plan
  -> AgentRun.status = waiting_approval
  -> 返回 diagnosis + plan_preview + thread_id

POST /workspace/workflow/resume
  approval=approved
    -> commit_plan
    -> AgentRun.status = completed

  approval=rejected
    -> 不写任务
    -> AgentRun.status = cancelled
```

保留非工作流接口时，也要明确：

- `/workspace/diagnose-and-plan` 可以作为快速模式，但需要在响应中说明它会直接创建计划。
- 或者统一改为生成 `pending` 计划，由用户确认后才激活。

验收标准：

- 拒绝审批不会产生任何 `learning_tasks`。
- 批准审批后才产生任务。
- Trace Lab 能看到 `waiting_approval -> completed/cancelled` 状态变化。

### 4.3 Agent 失败处理统一化

当前问题：

- `/workspace/diagnose-and-plan` 没有完整 try/except。
- 诊断或规划任一步失败，会留下 running run 或半截 step。

设计：

新增轻量运行上下文：

```text
AgentRunContext
  start_step(name)
  complete_step(output, latency_ms)
  fail_step(error)
  complete_run(output)
  fail_run(error)
```

所有 Agent API 都通过同一套上下文写状态。

失败状态规则：

| 场景 | Run 状态 | Step 状态 | 前端展示 |
|---|---|---|---|
| 诊断失败 | failed | failed | 显示错误、可重试 |
| 规划失败 | failed | failed | 保留诊断结果，提示规划失败 |
| 等待审批 | waiting_approval | waiting_approval | 显示确认按钮 |
| 用户拒绝 | cancelled | skipped/cancelled | 显示已取消 |
| 工具失败但可降级 | completed | completed_with_warning | 显示 warning |

验收标准：

- Trace Lab 不再出现长期 running 的脏数据。
- 每个失败 run 都有 `error_message`。
- 每个失败 step 都有明确错误。

### 4.4 Tool Registry 接入真实 ToolCall

当前问题：

- `ToolRegistry.execute()` 计算了 `latency_ms`，但没有写入 `tool_calls`。
- `requires_approval` 没有真正参与执行。
- 工具输出 summary 偏固定。

设计：

`registry.execute()` 增加可选上下文：

```python
execute(
    name,
    arguments,
    db,
    user_id,
    run_id=None,
    step_id=None,
    approval_granted=False,
)
```

执行规则：

- 未注册工具：返回 `ToolResult(ok=False)` 并记录失败。
- 只读工具：直接执行。
- 写工具且 `requires_approval=True`：没有审批时返回 `needs_approval`，不执行。
- 执行成功/失败都写入 `tool_calls`。

统一输出：

```json
{
  "ok": true,
  "data": {},
  "summary": "创建了 5 个学习任务",
  "artifacts": [
    {"type": "learning_task", "id": "...", "title": "..."}
  ],
  "warnings": []
}
```

验收标准：

- Trace Run 详情能看到真实工具调用。
- 写工具未经审批不会改数据库。
- 工具失败不会吞掉错误。

### 4.5 学习路径模型统一

当前问题：

- `path_service.generate_learning_path()` 仍写 `modules_json`。
- `planner.plan()` 写结构化 `learning_path_modules / topics / tasks`。
- 普通路径和 Agent 路径割裂。

设计：

统一为结构化模型优先：

```text
LearningPath
  -> LearningPathModule
    -> LearningPathTopic
      -> LearningTask
```

兼容策略：

- `modules_json` 只作为旧数据兼容字段。
- 新生成路径必须写结构化表。
- API 返回时优先从结构化表组装；没有结构化数据时才回退 `modules_json`。
- Portfolio、Workspace、Paths 页面统一读结构化任务进度。

验收标准：

- `/paths/generate` 生成的路径会出现在今日任务体系中。
- Agent 规划和普通路径页面展示的是同一套数据。
- 不再出现“路径有了，但 Workspace 没任务”的割裂体验。

## 5. 前端设计

### 5.1 信息架构收拢

当前侧边栏菜单较多，用户会感觉功能分散。

推荐保持现有路由，但重新组织菜单分组：

```text
工作台
  概览
  Agent

知识库
  知识点
  导入知识
  AI 对话

训练
  间隔复习
  学习路径
  模拟面试

实验室
  Trace Lab
  Portfolio

系统
  设置
```

设计目标：

- 不删除已有功能。
- 让用户理解产品主线：工作台 -> 知识库 -> 训练 -> 实验室。
- 面试演示时路径更清楚。

### 5.2 Dashboard 升级为“今日学习工作台”

当前 Dashboard 是统计卡片和最近数据。

新定位：

**用户打开应用后，第一眼知道今天该做什么。**

页面结构：

```text
顶部：今日状态
  待复习 / 待学习任务 / Agent 建议 / 连续学习

主区域左：今日任务队列
  学习任务
  复习任务
  面试任务
  导入整理任务

主区域右：Agent 建议
  当前薄弱点
  推荐下一步
  最近一次 Agent Run 状态

下方：学习进度与质量
  掌握度分布
  RAG 反馈
  最近面试得分
  AI 成本概览
```

交互：

- 每个任务有明确动作按钮：学习、复习、面试、查看路径。
- 空状态不只是“暂无数据”，而是给出一个主操作：导入知识或运行 Agent 规划。
- 避免大段说明文字，靠任务和状态引导。

### 5.3 Agent Workspace 升级为“执行台”

当前 Agent Workspace 是输入框 + 诊断卡 + 计划卡 + 今日任务。

新布局：

```text
左侧：运行控制
  学习目标输入
  运行类型：诊断 / 规划 / 面试准备
  当前 run 状态
  历史 run 快捷入口

中间：Agent 产物
  诊断摘要
  薄弱点列表
  计划预览
  待审批任务

右侧：实时 Trace
  step timeline
  tool calls
  LLM token/cost
  error/warning

底部或抽屉：审批队列
  批准
  编辑后批准
  拒绝
```

核心体验：

```text
输入目标
  -> Agent 诊断
  -> 生成计划预览
  -> 用户审批
  -> 创建任务
  -> 今日工作台出现下一步
```

视觉重点：

- Agent 状态要清楚：running / waiting approval / completed / failed。
- 计划预览不要像普通列表，要像可执行任务板。
- 右侧 Trace 让用户感知“Agent 真的在调用工具和推理流程”。

### 5.4 Trace Lab 升级为“运行回放”

当前 Trace Lab 已有运行表格、详情抽屉、步骤 timeline、工具表。

增强方向：

```text
顶部过滤：
  run_type / status / 日期 / 是否失败

主列表：
  类型、目标、状态、耗时、Token、成本、失败原因

详情抽屉：
  Overview
  Steps
  Tool Calls
  AI Calls
  Input / Output JSON
  Errors

RAG Eval Tab：
  feedback helpful rate
  eval runs
  failed cases
```

关键补强：

- 展示 step 的 input/output 摘要。
- 展示 tool_call arguments/result 摘要。
- 失败 run 默认突出显示错误和可重试入口。
- RAG 评估不要塞在普通卡片里，拆成独立 Tab 或区域。

### 5.5 Portfolio 升级为“面试展示页”

当前 Portfolio 是统计 + 报告生成 + run timeline。

新定位：

**让面试官快速理解你做了一个什么 AI Agent 系统。**

页面结构：

```text
项目摘要
  一句话定位
  技术栈
  核心能力矩阵

工程亮点
  Agent Runtime
  Tool Registry
  Human-in-the-loop
  RAG + Eval
  MCP Server
  LangGraph Adapter

代表性 Run
  目标
  步骤
  工具调用
  成本
  结果

质量指标
  后端测试数
  RAG feedback
  Agent success rate
  Lint/build 状态

导出
  项目技术报告 Markdown
  学习报告 Markdown
```

注意：

- Portfolio 不是普通 dashboard。
- 它应该讲清楚“技术故事”和“证据”，适合录屏、面试展示、README 截图。

### 5.6 视觉系统

当前页面大量白色卡片，容易显得普通。

V4.1 不需要大改品牌，但需要统一设计层级：

- 使用页面级工作区，而不是卡片套卡片。
- 卡片只用于独立内容块，不做层层包裹。
- 建立状态颜色：running、waiting、success、failed、cancelled。
- 建立 Agent 专属组件：RunStatusBadge、StepTimeline、ToolCallTable、ApprovalPanel、TaskQueue。
- 控制页面宽度：工作台页面可以 `max-w-7xl`，普通表单页面保持 `max-w-5xl`。
- 减少解释性文案，把说明变成状态、按钮和空状态动作。

## 7. API 调整建议

### Workspace

```text
GET  /workspace/overview
POST /workspace/diagnose
POST /workspace/plan-preview
POST /workspace/plans/{run_id}/approve
POST /workspace/plans/{run_id}/reject
GET  /workspace/tasks/today
GET  /workspace/tasks
PUT  /workspace/tasks/{id}/complete
```

如果继续保留 LangGraph 版本：

```text
POST /workspace/workflow/plan
POST /workspace/workflow/resume
```

语义要求：

- `plan-preview` 不落库任务。
- `approve` 才落库任务。
- `reject` 不产生任务。

### Trace

```text
GET /traces/runs?run_type=&status=&page=&page_size=
GET /traces/runs/{id}
GET /traces/ai-logs
GET /traces/stats
```

增强要求：

- runs 支持 status/run_type 过滤。
- run detail 返回 steps、tool_calls、ai_logs。
- JSON 字段前端可折叠展示。

### Portfolio

```text
GET  /portfolio/summary
GET  /portfolio/case-study
POST /portfolio/report/project
POST /portfolio/report/learning
GET  /portfolio/runs/recent
```

增强要求：

- `case-study` 返回固定结构，减少前端拼装。
- 报告生成可以继续复用现有接口。

## 8. 分阶段实施

### V4.1.1 安全与正确性

目标：先把危险点和语义错误修掉。

任务：

- MCP 默认关闭。
- MCP 绑定明确用户，移除 `_get_default_user()`。
- LangGraph plan 改成 preview/commit。
- `diagnose-and-plan` 加完整失败处理。
- `ToolRegistry.execute()` 写入真实 `tool_calls`。
- 写工具接入 `requires_approval`。

验收：

- 拒绝审批不产生任务。
- 失败 run 不会停留 running。
- MCP 不会访问第一个默认用户。
- 后端测试通过。

### V4.1.2 工程质量归零

目标：项目能稳定构建和检查。

任务：

- 修复前端 API 层 `any`。
- 修复 hooks 声明顺序和 lint 规则报错。
- 明确是否调整 `react-hooks/set-state-in-effect` 规则；如果规则过严，需要在 eslint 配置中做项目级决策，而不是逐页绕。
- 修复本地 Tailwind native 依赖问题。
- 保证 `tsc`、`lint`、`build` 都通过。

验收：

- `npx tsc -b --pretty false` 通过。
- `npm run lint` 通过。
- `npm run build` 通过。
- 后端 `pytest` 通过。

### V4.1.3 主工作台体验升级

目标：解决“前端页面简单”和“功能分散”的观感。

任务：

- 重组侧边栏分组。
- Dashboard 改成今日学习工作台。
- Agent Workspace 改成三栏执行台。
- 任务队列统一展示学习、复习、面试、导入整理。
- 空状态给出明确下一步。

验收：

- 新用户知道从哪里开始。
- 老用户打开首页知道今天做什么。
- Agent 执行过程可见。
- 移动端或窄屏不出现文字重叠。

### V4.1.4 Trace 与 Portfolio 展示增强

目标：让项目更适合面试展示。

任务：

- Trace Lab 增加过滤、详情 Tabs、input/output JSON 展示。
- ToolCall 和 AI Call 显示耗时、成本、错误。
- RAG Eval 从卡片升级成独立区域。
- Portfolio 改成项目案例展示页。
- 增加代表性 Run 回放。

验收：

- 可以用 Portfolio 页面讲清楚项目架构。
- 可以用 Trace Lab 证明 Agent 可观测。
- 可以展示一次完整 Agent run 的目标、步骤、工具、成本和结果。

## 9. 测试策略

### 后端测试

新增测试重点：

- MCP 未启用时不可访问。
- MCP 配置用户后只访问该用户数据。
- `preview_plan` 不创建任务。
- `commit_plan` 创建结构化路径和任务。
- `reject` 不创建任务。
- `diagnose-and-plan` 中间异常时 run/step 变为 failed。
- ToolRegistry 执行成功/失败都记录 tool_call。
