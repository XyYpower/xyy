# KnowBase V3.1 / V4.0 — AI Agent 应用开发重设计方案

> 目标：把 KnowBase 从“AI 编程知识学习工具”升级为 **可展示 AI Agent 应用开发能力的 Agentic Learning OS**。
>
> 这份文档不推翻 `Phase2-design.md`，而是在已经完成的认证、知识点、复习、导入、学习路径、RAG 对话、模拟面试和导出能力之上，设计下一阶段最优架构。

---

## 1. 结论先行

### 最优方向

KnowBase 下一阶段不要继续简单堆功能，而要把已有能力重组成一个可追踪、可评估、可人工确认的 Agent 工作台：

```text
学习目标
  -> 诊断 Agent 识别薄弱点
  -> 规划 Agent 生成可执行学习路径
  -> 导入/整理 Agent 把资料转成高质量知识点
  -> 学习教练 Agent 安排每日任务与复习
  -> 面试教练 Agent 动态追问和评分
  -> 评估系统记录效果、成本、失败原因
  -> 作品集视图展示 Agent 运行过程和学习成果
```

### 一句话定位

**KnowBase 是面向开发者的 AI Agent 学习工作台：它不只是回答问题，而是会诊断、规划、整理、复习、面试和复盘。**

### 为什么这是最优方案

- 贴合现有代码：当前已经有 `notes`、`review_cards`、`import_jobs`、`learning_paths`、`conversations`、`interview_sessions`，不用大拆重写。
- 贴合岗位能力：AI Agent 应用开发岗位看重工具调用、工作流编排、RAG、人工确认、可观测性、评估、成本控制和部署。
- 贴合作品集：面试官可以看到一个完整 Agent 系统如何拆模块、调用工具、追踪步骤、处理失败，而不是只看到一个聊天框。
- 控制复杂度：先做轻量 Agent Runtime 和工具注册，再按需接入 LangGraph / MCP，避免一开始被框架绑住。

## 2. 当前项目诊断

### 已经做得好的部分

| 能力 | 当前实现 | 价值 |
|---|---|---|
| 用户与数据隔离 | JWT + user_id | 可作为真实应用基础 |
| 知识点管理 | notes / tags / categories | 已有学习内容载体 |
| AI 导入 | import_jobs + extraction_drafts | 已有 human-in-the-loop 雏形 |
| RAG 对话 | note_chunks + pgvector + SSE | 已有核心 AI 应用能力 |
| 间隔复习 | review_cards + SM-2 | 有独特产品闭环 |
| 模拟面试 | session + questions + AI 评分 | 可形成诊断数据 |
| 导出 | JSON / Markdown / Anki | 便于迁移和展示 |
| 前端体验 | Ant Design + Markdown 编辑器 | 已可作为完整产品演示 |

### 主要短板

| 短板 | 当前表现 | 优化方向 |
|---|---|---|
| Agent 感不足 | 功能是分散 API，不是统一工作流 | 增加 Agent Run / Step / ToolCall |
| 缺少可观测性 | Chat/Import/Interview 没有统一 trace | 记录每一步输入、输出、耗时、错误和成本 |
| 缺少评估体系 | RAG 好坏、面试评分质量无法量化 | 建立 eval_cases / eval_runs / eval_results |
| 学习路径太静态 | `modules` 是 JSONB，缺少 topic 级进度 | 拆成 module/topic/progress/evidence |
| RAG 检索偏 MVP | 只有向量相似度，无关键词混合、重排、引用片段质量 | 做 hybrid retrieval + rerank + citation spans |
| AI 调用成本不可见 | `Phase2-design.md` 设计了 `ai_call_logs`，但当前未落地 | V3.1 优先补齐 |
| 缺少工具边界 | 服务函数不能被 Agent 统一调用和审计 | 建立 Tool Registry |
| 缺少作品集展示面 | 用户能用，但不容易向面试官解释技术亮点 | 新增 Agent 工作台、Trace Lab、Portfolio 页面 |
| 缺少 MCP 能力 | 不能被外部 Agent/IDE 调用 | V4.0 暴露 MCP Server |

## 3. 产品重设计

### 3.1 新主界面：Agent Workspace

新增页面：`frontend/src/pages/AgentWorkspace.tsx`

核心体验：

```text
顶部：输入学习目标 / 当前任务
左侧：Agent 生成的计划和步骤
中间：当前步骤的产物、草稿、回答、引用来源
右侧：Trace 面板，展示检索、工具调用、LLM 调用、耗时、成本
底部：人工确认队列，用户可以批准、编辑、拒绝 Agent 动作
```

示例任务：

```text
我想 3 个月后面试 AI Agent 应用开发岗位，帮我规划并开始执行。
```

Agent 应该输出：

- 当前知识库诊断结果
- 需要补齐的能力图谱
- 8 周学习路径
- 本周任务
- 今天需要导入/学习/复习/面试的项目
- 每一步使用了哪些工具和知识点

### 3.2 学习路径升级：从静态 JSON 到可执行路线

当前 `learning_paths.modules` 是 JSONB，适合 MVP，但不适合长期追踪。

建议新增结构化表：

```text
learning_path_modules
  id, path_id, title, description, order_index, status

learning_path_topics
  id, module_id, title, objective, status, priority,
  linked_note_id, evidence_type, evidence_ref, mastery_score

learning_tasks
  id, user_id, topic_id, task_type, title, status,
  due_at, completed_at, agent_run_id
```

Topic 状态：

```text
not_started -> learning -> reviewing -> interview_ready -> mastered
```

这样学习路径不再只是“AI 写的一段计划”，而是每天能推动用户行动的任务系统。

### 3.3 Agent 角色划分

| Agent | 职责 | 主要工具 |
|---|---|---|
| DiagnosisAgent | 根据笔记、复习、面试历史诊断薄弱点 | notes.search, review.stats, interview.weak_points |
| PlannerAgent | 把目标拆成路径、模块、topic、每日任务 | paths.create, tasks.create |
| CuratorAgent | 导入 URL/文本/代码，提取知识点草稿，去重和归类 | import.create, drafts.update, notes.create |
| RetrievalAgent | 负责 RAG 检索、引用和上下文压缩 | retrieval.search, notes.get |
| StudyCoachAgent | 安排每日学习、复习和提醒 | review.today, tasks.next |
| InterviewCoachAgent | 动态出题、追问、评分、总结 | interview.start, interview.answer |
| PortfolioAgent | 生成项目展示材料、学习报告和 README | export.markdown, reports.create |

首期不需要真的做多模型多进程 Agent。可以先用同一个 LLM 客户端，根据 `agent_type` 和工具集合区分角色。

## 4. 后端架构重设计

### 4.1 推荐架构：轻量 Agent Runtime 优先

不要 V3.1 一上来直接全面迁移 LangGraph。最稳的路线是：

```text
V3.1：自建轻量 Agent Runtime，完成工具注册、运行记录、trace、成本日志
V3.2：把核心学习工作流接入 Runtime，形成 Agent Workspace
V3.3：补评估、RAG 优化和数据集回放
V4.0：对复杂长任务接入 LangGraph，对外暴露 MCP Server
```

原因：

- 当前服务层已经清晰，直接包装成工具成本低。
- LangGraph 很适合长任务、持久化、human-in-the-loop，但直接引入会改变调试方式和依赖面。
- 轻量 Runtime 先把数据模型和前端展示打牢，后续可把 executor 替换为 LangGraph adapter。

### 4.2 新增 Agent Runtime 模块

建议新增目录：

```text
backend/app/agents/
  __init__.py
  runtime.py          # AgentRun 执行入口
  registry.py         # Tool Registry
  schemas.py          # 工具输入/输出 Pydantic schema
  policies.py         # 权限、预算、人工确认策略
  traces.py           # trace/span 记录
  prompts.py          # Agent 系统提示词
  workflows/
    learning_plan.py  # 目标诊断 + 路径规划
    curate_import.py  # 导入整理
    daily_coach.py    # 每日学习教练
    interview.py      # 面试教练
```

#### eval_cases / eval_runs / eval_results

建立最小评估系统。

```text
eval_cases
  id, user_id, name, case_type, input, expected_output, tags, created_at

eval_runs
  id, user_id, name, target_type, target_version, status, created_at, finished_at

eval_results
  id, eval_run_id, eval_case_id, score, metrics, actual_output, error_message
```

首批评估类型：

- `rag_groundedness`：回答是否基于引用来源
- `rag_relevance`：检索结果是否命中正确知识点
- `answer_format`：输出是否满足 JSON/Pydantic schema
- `interview_scoring_consistency`：同一答案评分是否稳定
- `tool_success_rate`：工具调用成功率


### 5.2 工具权限

| 工具类型 | 是否需要确认 | 示例 |
|---|---|---|
| 只读工具 | 不需要 | notes.search, retrieval.search, review.stats |
| 生成草稿 | 不需要，但产物进入待确认 | imports.create_text_job, review.generate_cards |
| 写入用户知识库 | 需要确认 | notes.create, imports.confirm |
| 删除/批量修改 | 必须确认 | notes.delete, tags.merge |
| 外部访问 | 需要策略限制 | imports.create_url_job |

### 5.3 工具输出规范

所有工具返回统一 envelope：

```json
{
  "ok": true,
  "data": {},
  "summary": "创建了 3 个知识点草稿",
  "artifacts": [
    {"type": "draft", "id": "uuid", "title": "RAG 检索优化"}
  ],
  "warnings": []
}
```

这样前端可以统一展示结果，Agent 也能读取结构化产物。

## 6. RAG 优化方案

### 6.1 从纯向量检索升级到 Hybrid Retrieval

当前：

```text
query -> embedding -> pgvector top_k -> prompt
```

建议：

```text
query
  -> query rewrite
  -> vector search top 20
  -> keyword search top 20
  -> metadata filter(category/tag/source/mastery)
  -> merge + rerank top 6
  -> citation spans
  -> answer
```

### 6.2 新增 chunk 元数据

`note_chunks` 建议补充：

```text
token_count
section_title
source_start_offset
source_end_offset
embedding_model
embedding_status
```

价值：

- 引用可以定位到具体片段。
- 内容更新后能判断 embedding 是否过期。
- 不同 embedding 模型可以灰度切换。

### 6.3 RAG 质量反馈

在 Chat 页面加两个轻量动作：

```text
回答有帮助 / 没帮助
引用准确 / 引用不相关
```

落库到：

```text
message_feedback
  id, message_id, user_id, rating, issue_type, comment, created_at
```

这些反馈后续进入 eval_cases，形成真实评估数据集。

## 8. 安全、成本与可靠性

### 8.1 安全策略

- URL 导入继续保留 SSRF 防护，并增加 content-type / size limit。
- Agent 工具默认最小权限，写操作必须走 approval。
- 外部内容进入 RAG 前标记为 untrusted，不允许覆盖系统指令。
- LLM JSON 输出必须经过 Pydantic schema 校验。
- Agent trace 不保存完整敏感 prompt，只保存摘要、结构化输入和必要错误。

### 8.2 成本策略

- 每次 AgentRun 设置 token/cost budget。
- RAG 默认使用便宜模型，Portfolio 报告等少量高价值任务可用更强模型。
- Embedding 按 content_hash 去重。
- 复习和面试历史查询不重复调 AI。
- `ai_call_logs` 按 purpose 聚合成本，Dashboard 展示本周/月消耗。

### 8.3 可靠性策略

- AgentRun 可取消。
- 每个 Step 幂等，失败可重试。
- 长任务先用数据库状态机实现，后续再引入队列或 LangGraph checkpoint。
- SSE 断连时停止继续消耗 LLM API。
- 工具调用失败返回结构化错误，让 Agent 可以选择重试、降级或请求用户确认。

## 9. 分阶段路线图

### V3.1 — Agent Runtime + Trace 基础

目标：先让所有 AI 行为“看得见、算得清、能复盘”。

交付：

- 新增 `agent_runs`、`agent_steps`、`tool_calls`、`ai_call_logs`
- 新增 `backend/app/agents/registry.py`
- 把现有 Import / Chat / Interview / Path 的 AI 调用接入日志
- 新增 `Trace Lab` 基础页面
- Dashboard 增加 AI 调用次数、失败率、成本
- 后端测试覆盖工具注册、trace 写入、成本日志

不做：

- 不引入 LangGraph
- 不做 MCP
- 不做复杂多 Agent 自动循环

### V3.2 — Agent Workspace + 学习规划 Agent

目标：把“我想学 AI Agent 应用开发”变成可执行任务。

交付：

- Agent Workspace 页面
- DiagnosisAgent：根据 notes/review/interview 诊断薄弱点
- PlannerAgent：生成结构化 path/module/topic/task
- 拆分 `learning_paths.modules` 为结构化表
- 人工确认队列：确认后才写入学习任务和知识点
- 每日任务流：今天学什么、复习什么、面试什么

### V3.3 — RAG 质量与评估系统

目标：让项目具备工程级质量闭环。

交付：

- Hybrid retrieval
- citation spans
- message_feedback
- eval_cases / eval_runs / eval_results
- RAG 回归评估命令
- 面试评分一致性评估
- Trace Lab 展示 eval 结果

### V3.4 — Portfolio Builder

目标：让项目直接服务求职。

交付：

- Portfolio 页面
- 一键生成项目技术报告
- 一键生成“AI Agent 应用开发学习报告”
- 代表性 Agent Run 回放
- 导出可放进简历/GitHub README 的 Markdown

### V4.0 — LangGraph / MCP 生产化升级

目标：对齐 Agent 工程岗位更高级能力。

交付：

- LangGraph adapter：用于长任务、暂停/恢复、human-in-the-loop
- MCP Server：让外部 IDE/Agent 调用 KnowBase 的资源和工具
- MCP resources：
  - `knowbase://notes/{id}`
  - `knowbase://paths/{id}`
  - `knowbase://reviews/today`
- MCP tools：
  - `search_notes`
  - `create_note_draft`
  - `get_review_cards`
  - `generate_interview_questions`
- MCP prompts：
  - `prepare_agent_engineer_interview`
  - `explain_knowledge_gap`
  - `generate_project_case_study`

## 10. 面试展示话术

项目可以这样介绍：

```text
KnowBase 原本是一个 AI 知识库，我把它升级成了 Agentic Learning OS。
它不是简单 Chatbot，而是有工具调用、RAG、人工确认、间隔复习、模拟面试、运行追踪和评估闭环。

架构上我把原有业务服务封装成 Tool Registry，通过 AgentRun / AgentStep / ToolCall 记录每次 Agent 执行。
所有写操作都需要 human-in-the-loop 确认，AI 调用会记录 token、成本、耗时和错误。
RAG 部分用 pgvector 做向量检索，后续升级为 hybrid retrieval 和 citation spans，并用 eval_cases 做回归评估。

这个项目展示的是：我不仅会调 LLM API，还能把 Agent 做成一个可维护、可观测、可评估的真实应用。
```
